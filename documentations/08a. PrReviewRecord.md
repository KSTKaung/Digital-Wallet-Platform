### First review round (`security-reviewer`, `database-reviewer`, `code-reviewer`)
No Critical findings. Verdict: not ready to merge.

**The one High: account pre-hijack (H1 in the security report).** An attacker registers `victim@x` with their own password. The real owner registers later, gets the same `201`, and their password is dropped. When the owner verifies the emailed code, the row holding the **attacker's** password and phone becomes active.
**Fix:** re-registering an unverified account replaces its password and phone and cancels the old code, and `verify-otp` for registration also requires the password. A code alone no longer activates anything.

## PR 4b: Idempotency, deposits, withdrawals and wallet lookup
**Status:** in review on `feature/pr4b-money-movements`; not yet merged.

### Decisions
The plan was accepted with PR 4 on 2026-11-03 (doc 08 §4B). Decided during the work:
- **No money emails in PR 4b.** Deposit, withdrawal and transfer emails come together in PR 5, after D29 (outbox retention).
- **V1–V4, keys:**
  - an expired key is checked on every request and replaced under its row lock;
  - insufficient balance, the two limits and frozen are stored and replayed;
  - `KYC_REQUIRED` doesn't consume the key;
  - the header must be UUID v4 with the RFC variant;
  - a replay returns the original business response with fresh request metadata.
- **W1–W5, money requests:**
  - the deposit note is optional and not returned;
  - the response shows the server reference;
  - `fundingSource` is refused on this endpoint only, with global JSON handling unchanged;
  - below the minimum is `400` and doesn't consume the key;
  - each stored refusal gets one `FAILURE` audit row.
- **X1–X6, lookup:**
  - caller codes `403 KYC_REQUIRED` and `409 WALLET_FROZEN`;
  - format and check digit are separate steps;
  - status and rate-limit refusals are neither counted nor audited;
  - attempts are kept for the 1-minute window;
  - the number is masked as `*******` plus the last 4 digits;
  - not-found audit rows record only `NOT_FOUND`.
