## 1. Principles

- **Backend-first.** Java 21 / Spring Boot microservices own money, KYC, and authorization. React is a thin demo SPA (`17. FrontendUi.md`).
- **Final wins.** Do not re-adopt a modular monolith (ADR-002). Do not invent a ninth “transaction service.”
- **No 2PC.** Each service commits locally. Cross-service facts go via outbox → Kafka for **side effects only**.
- **OpenAPI paths.** Public `/api/v1/**` through the Gateway. Ledger and risk evaluate stay `/internal/v1/**`.
- **Database-per-service.** No SQL joins across DBs; IDs in events or REST only (ERD §10).
- **One money model.** Wallet: `available_balance`, `reserved_balance`, `version`. Ledger: append-only balanced debit/credit on the **request path**.

## 5. Engineering guardrails

- **Git:** `feature/*` → PR → squash to `main`; Conventional Commits; no secrets ([03. GitStrategy.md](12.%20TechnologyDocument/03.%20GitStrategy.md)).
- **Flyway:** append-only after merge; one migration stream **per** service database.
- **Tests:** domain unit tests; Testcontainers for auth and money paths.
- **Idempotency:** header on deposits, withdrawals, transfers, payments, refunds.
- **Tags:** `v0.1.0` Identity … `v1.0.0` demo deploy (GitStrategy table).
- **Frontend:** only Gateway; no `/internal/v1`; `Idempotency-Key` on money POSTs.
