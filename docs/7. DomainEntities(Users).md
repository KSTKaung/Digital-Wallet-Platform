## 3. Define Relationships
### Customer → Wallet
A customer owns one primary wallet in the MVP.
> Customer 1 ─────────── 1 Wallet

### Customer → Transactions
A customer can have many transactions.
> Customer 1 ─────────── * Transaction

### Wallet → Transactions
A wallet can participate in many transactions.
> Wallet 1 ─────────── * Transaction

### Merchant → Payment
A merchant can receive many payments.
> Merchant 1 ─────────── * Payment

### Customer → Payment
A customer can make many payments.
> Customer 1 ─────────── * Payment

### Transfer → Transaction
A transfer represents a business operation, while the transaction represents the financial movement.
> Transfer 1 ─────────── 1 Transaction

### Transaction → Ledger Entries
A transaction can generate multiple ledger entries.
> Transaction 1 ─────────── * LedgerEntry

**For a simple transfer:**
```
Transaction
     │
     ├── Debit LedgerEntry
     │
     └── Credit LedgerEntry
```

## 5. Define Business Rules
### 5.1 Customer Rules
***BR-CUST-001***  
A customer must verify their identity before performing restricted financial operations.

***BR-CUST-002***  
A frozen customer cannot initiate financial transactions.

***BR-CUST-003***  
A customer can access only their own wallet information.

### 5.2 Wallet Rules
***BR-WALLET-001***
Wallet balance cannot become negative.

***BR-WALLET-002***
Deposit amount must be greater than zero.

***BR-WALLET-003***
Withdrawal amount must be greater than zero.

***BR-WALLET-004***
Withdrawal cannot exceed available balance.

***BR-WALLET-005***
Frozen wallets cannot perform financial transactions.

### 5.3 Transfer Rules
***BR-TRANSFER-001***
Sender and recipient must be active.

***BR-TRANSFER-002***
Sender must have sufficient available balance.

***BR-TRANSFER-003***
Transfer amount must be greater than zero.

***BR-TRANSFER-004***
Transfer must not exceed the customer's transaction limit.

***BR-TRANSFER-005***
Transfer must not exceed the customer's daily limit.

***BR-TRANSFER-006***
A transfer request must have an idempotency key.

***BR-TRANSFER-007***
A successful transfer must create corresponding ledger entries.

### 5.4 Payment Rules
***BR-PAYMENT-001***
Merchant must be active.

***BR-PAYMENT-002***
Customer must have sufficient balance.

***BR-PAYMENT-003***
Payment amount must be greater than zero.

***BR-PAYMENT-004***
Expired QR codes cannot be used.

***BR-PAYMENT-005***
Customer must confirm the payment before execution.

### 5.5 Refund Rules
***BR-REFUND-001***
Refund must reference an original payment.

***BR-REFUND-002***
Refund amount cannot exceed the original payment amount.

***BR-REFUND-003***
A completed payment cannot be refunded more than once.

***BR-REFUND-004***
Refund must create a corresponding financial transaction.

### 5.6 KYC Rules
***BR-KYC-001***
Customer must submit all required documents.

***BR-KYC-002***
Only authorized compliance users can approve KYC.

***BR-KYC-003***
Rejected KYC applications must contain a rejection reason.

***BR-KYC-004***
Only verified customers can access restricted financial services.

## 9. Service Responsibility Matrix
| Service        | Owns                             | Should NOT Own                |
| -------------- | -------------------------------- | ----------------------------- |
| Identity       | Authentication, tokens, sessions | Wallet balance                |
| Customer       | Customer profile                 | Transactions                  |
| KYC            | KYC applications                 | Wallet balance                |
| Wallet         | Wallet lifecycle                 | Authentication                |
| Ledger         | Financial entries                | Customer profile              |
| Transfer       | Transfer workflow                | User passwords                |
| Payment        | Payment workflow                 | Ledger records                |
| Merchant       | Merchant data                    | Customer wallet               |
| Notification   | Notifications                    | Financial transactions        |
| Fraud          | Risk evaluation                  | Wallet balance                |
| Settlement     | Settlement processing            | Customer authentication       |
| Reconciliation | Matching financial records       | User profile                  |
| Admin          | Administration/RBAC              | Direct financial modification |
| Reporting      | Read/report models               | Source-of-truth transactions  |
| Audit          | Audit events                     | Business transactions         |
