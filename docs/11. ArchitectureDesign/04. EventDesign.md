# Event Design
## Event Architecture
**The overall flow:**
```
┌──────────────────┐
│   Wallet Service │
└────────┬─────────┘
         │
         │ MoneyDeposited
         ▼
┌──────────────────┐
│      Kafka       │
└────────┬─────────┘
         │
    ┌────┼───────────────┐
    ▼    ▼               ▼
Notification  Ledger   Audit
 Service      Service   Service
```

**For transfers:**
```
Transfer Service
       │
       │ TransferCompleted
       ▼
     Kafka
       │
       ├──────────────► Notification Service
       │
       ├──────────────► Audit Service
       │
       └──────────────► Analytics/Risk Service
```

## Event Envelope
```
{
  "eventId": "7f4c1a...",
  "eventType": "TransferCompleted",
  "eventVersion": 1,
  "occurredAt": "2026-08-18T12:30:00Z",
  "producer": "transfer-service",
  "correlationId": "abc-123",
  "causationId": "xyz-456",
  "payload": {
    "transferId": "transfer-123",
    "senderWalletId": "wallet-001",
    "receiverWalletId": "wallet-002",
    "amount": 10000.00,
    "currency": "THB"
  }
}
```
**eventId**
Used for duplicate detection.

**eventType**
Identifies the business event.

**eventVersion**
Allows event schema evolution.

**occurredAt**
When the business event happened.

**producer**
Identifies the originating service.

**correlationId**
Tracks an entire business request across services.

**causationId**
Identifies which event/request caused this event.

## Event Idempotency
```

       │
       ▼
Notification Service
       │
       ├── First delivery → process
       │
       └── Duplicate      → ignore
```

```
Receive Event
     │
     ▼
Check eventId
     │
 ┌───┴────┐
 │        │
Exists   New
 │        │
 ▼        ▼
Ignore   Process
          │
          ▼
    Save eventId
```

## Event Design Rules
### Rules 
1. Events are immutable  
**Example:**
```
Once published:                     TransferCompleted
If something needs to be corrected: TransferReversed
```
2. Events use past tense  
**Example:**
```
MoneyDeposited
TransferCompleted
PaymentRefunded
```
3. Every event has a unique ID  
**Example:**
 ```
eventId is mandatory.
 ```
4. Events are versioned  
**Example:**
```
eventVersion: 1
Leter
eventVersion: 2
```
5. Never expose sensitive data  
**Example:**
```
Do not put:
_password
passwordHash
JWT
refreshToken
full card number
CVV_
inside Kafka events.
```
6. Use correlation IDs  
A single transfer should be traceable:
```
HTTP Request
    ↓
Transfer
    ↓
Wallet
    ↓
Ledger
    ↓
Notification
    ↓
Audit
```
using > correlationId
