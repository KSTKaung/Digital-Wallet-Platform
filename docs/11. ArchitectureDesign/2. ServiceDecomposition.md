# Service Decomposition
## Target architecture
> API Gateway + Microservices + DDD + Clean Architecture + Event-Driven Communication

## Eight core business services + Three infrastructure components.
Business Services  
├── 1. Authentication / Identity Service  
├── 2. Customer & KYC Service  
├── 3. Wallet Service  
├── 4. Transfer Service  
├── 5. Payment & Merchant Service  
├── 6. Ledger Service  
├── 7. Risk & Notification Service  
└── 8. Admin & Operations Service  
  
Infrastructure  
├── 9. API Gateway  
├── 10. Config Server  
└── 11. Service Discovery Server  

## Authentication / Identity Service
**Responsibility**
Handles identity and authentication.
**Features**
- Registration
- Login
- Logout
- JWT
- Refresh Token
- OTP
- Password Management
- Session Management
- Authentication

**APIs**
```
POST /api/v1/auth/register
POST /api/v1/auth/login
POST /api/v1/auth/refresh
POST /api/v1/auth/logout

POST /api/v1/auth/verify-otp
POST /api/v1/auth/resend-otp

POST /api/v1/auth/forgot-password
POST /api/v1/auth/reset-password
POST /api/v1/auth/change-password
```

**Own Database**
```
identity_db
├── users
├── credentials
├── refresh_tokens
├── sessions
└── otp_verifications
```

**Publishes Events**
- UserRegistered
- UserVerified
- UserLoggedIn
- UserPasswordChanged

## Customer & KYC Service
**Responsibility**
Manages customer information and identity verification.

**Features**
- Customer Profile
- Customer Status
- KYC Application
- KYC Documents
- KYC Verification
- Customer Verification Status

**APIs**
```
GET  /api/v1/customers/me
PUT  /api/v1/customers/me

POST /api/v1/kyc/applications
GET  /api/v1/kyc/applications/{id}
POST /api/v1/kyc/applications/{id}/submit

GET /api/v1/kyc/status
```

**Own Database**
```
customer_db
├── customers
├── customer_profiles
├── kyc_applications
└── kyc_documents
```

**Publishes Events**
- CustomerCreated
- KycSubmitted
- KycApproved
- KycRejected
- CustomerSuspended

## Wallet Service (one of the core financial services)
**Features**
- Wallet
- Balance
- Deposit
- Withdrawal
- Wallet Status
- Wallet Limits

**APIs**
```
GET  /api/v1/wallet
GET  /api/v1/wallet/balance

POST /api/v1/wallet/deposits
POST /api/v1/wallet/withdrawals

GET  /api/v1/wallet/limits
GET  /api/v1/wallet/status

POST /api/v1/wallet/freeze
POST /api/v1/wallet/unfreeze
```

**Own Database**
```
wallet_db
├── wallets
├── wallet_limits
└── wallet_status_history
```

**Important Rules**
- Amount must be positive
- Wallet must exist
- Wallet must be active
- No overdraft
- Withdrawal limit must be enforced

**Publishes Events**
- DepositCompleted
- WithdrawalCompleted
- WalletFrozen
- WalletUnfrozen

## Transfer Service
**Responsibility**
Handles customer-to-customer money transfers.

**Features**
- Transfer
- Beneficiary
- Transfer Limits
- Transfer Status
- Idempotency
- Transfer Validation

**APIs**
```
POST /api/v1/transfers

GET  /api/v1/transfers
GET  /api/v1/transfers/{id}

GET  /api/v1/transfers/{id}/status

POST /api/v1/transfers/{id}/cancel
```
**Beneficiary APIs:**
```
GET    /api/v1/beneficiaries
POST   /api/v1/beneficiaries
GET    /api/v1/beneficiaries/{id}
PUT    /api/v1/beneficiaries/{id}
DELETE /api/v1/beneficiaries/{id}
```

**Own Database**
```
transfer_db
├── transfers
├── beneficiaries
├── transfer_limits
└── idempotency_records
```

**Important Rules**
- Sender must have sufficient balance
- Sender cannot transfer to self
- Amount must be positive
- Daily limit must be enforced
- Transfer must be atomic
- Duplicate requests must not create duplicate transfers

**Publishes Events**
- TransferInitiated
- TransferCompleted
- TransferFailed
- TransferCancelled
