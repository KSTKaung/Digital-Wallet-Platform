## 2. Domain Analysis
### Domain 1 — Identity & Authentication
**Purpose**
Responsible for identifying users and controlling authentication.

**Main Responsibilities**
- Customer registration
- Login
- Logout
- OTP verification
- Password management
- Refresh tokens
- MFA
- Device management
- Session management

**Entities**
- User
- Credential
- RefreshToken
- OTP
- Session
- Device
- MFAConfiguration

**Example APIs:**
```
POST /api/v1/auth/register
POST /api/v1/auth/login
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
POST /api/v1/auth/verify-otp
POST /api/v1/auth/change-password
POST /api/v1/auth/reset-password
```

### Domain 4 — Ledger & Transaction Domain (Important Domain)
**Purpose**
Maintains the financial record of every money movement.

**Responsibilities**
- Transaction creation
- Debit
- Credit
- Transaction status
- Financial history
- Double-entry ledger
- Transaction reversal
- Idempotency

**Entities**
- Transaction
- LedgerEntry
- Account
- DebitEntry
- CreditEntry
- TransactionReference

**Important Concept**
```
Transaction
     │
     ├── Debit Entry
     │      └── Sender Account
     │
     └── Credit Entry
            └── Receiver Account
```

**Example:**
```
Transfer 1,000 THB

Sender Ledger
    DEBIT  1,000

Receiver Ledger
    CREDIT 1,000
```

**Purpose**

**Responsibilities**

**Entities**

**Example Rules:**
```
IF transaction > daily limit
    → HIGH RISK

IF new device + high-value transfer
```
