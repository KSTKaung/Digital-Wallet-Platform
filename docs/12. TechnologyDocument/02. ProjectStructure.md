# Digital Wallet Platform — Technical Planning
## Detailed Project Structure

Repository layout matches Final Architecture §10. Each **business service is its own Spring Boot module** with Clean Architecture packages inside.

### Detailed Structure — Single Service (e.g. wallet-service)
```
wallet-service/
├── src/main/java/com/platform/wallet/
│   ├── domain/                  # pure Java — no Spring, JPA, Kafka
│   │   ├── model/               # Wallet, WalletId, Money, WalletStatus
│   │   ├── repository/          # ports (interfaces)
│   │   ├── service/
│   │   ├── exception/
│   │   └── event/
│   ├── application/
│   │   ├── usecase/             # DepositUseCase, WithdrawUseCase, …
│   │   ├── dto/
│   │   ├── mapper/
│   │   └── port/in|out
│   ├── infrastructure/
│   │   ├── persistence/         # JpaEntity, Spring Data, adapters
│   │   ├── messaging/           # outbox + Kafka publisher
│   │   ├── cache/               # Redis idempotency
│   │   └── client/              # Ledger internal REST client
│   ├── presentation/
│   │   └── rest/                # WalletController — /api/v1/wallet/**
│   ├── config/
│   └── security/
├── src/main/resources/
│   └── db/migration/            # Flyway for wallet_db only
├── src/test/java/
├── Dockerfile
└── pom.xml
```

Ledger-service exposes **only** `/internal/v1/ledger/**`. Transfer-service and wallet-service call it; the Gateway does not route those paths.

### Shared conventions (every business service)
```
presentation  →  application  →  domain
                       ↑
                infrastructure
```
- **domain** depends on nothing else.
- **application** depends only on **domain** and defines ports.
- **infrastructure** implements ports (JPA, Kafka, Redis, WebClient to Ledger/Risk).
- **presentation** depends only on **application**.

### Traced Example: Transfer (Final sequence)
- Gateway `POST /api/v1/transfers` → **transfer-service** presentation
- Use case: idempotency → limits → internal **risk** evaluate → **wallet-service** debit/credit (snapshot + `version`) → **ledger-service** `POST /internal/v1/ledger/entries`
- Same local DB transaction in Transfer: `transfers` + `outbox_events`
- Outbox job publishes `TransferCompleted` to Kafka → notification / audit consumers

| ------------------- | --------------------- | ------- |
| Domain model        | (none — plain noun)   | Wallet, Money |
| Domain port         | Repository / Port     | WalletRepository |
| Use case            | UseCase               | TransferFundsUseCase |
| App port (outbound) | Port                  | LedgerPort |
| Infra adapter       | Adapter               | WalletRepositoryAdapter |
| JPA entity          | JpaEntity             | WalletJpaEntity |
| REST DTO            | Request / Response    | TransferRequest |
| Domain event        | Event (past tense)    | WalletDebitedEvent |
