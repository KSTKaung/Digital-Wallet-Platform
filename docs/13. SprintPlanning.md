# Digital Wallet Platform — Sprint Planning
## Sprint 1 — Infrastructure
**Goal:** Establish a working project skeleton and pipeline so every later sprint ships onto solid ground.

### Tasks
- Create Spring Boot Project
  - Initialize with Java 21 + Spring Boot 3.x (Web, JPA, Validation)
  - Set up package structure: **_domain / application / infrastructure / presentation / config / security / common_**
- Configure Maven
  - Dependency management, profiles (dev/prod)
  - Add Spotless/Checkstyle plugin for formatting
- Setup PostgreSQL
  - Docker Compose service for Postgres
  - Flyway baseline migration (**_V1__init.sql_**)
  - HikariCP pool sizing
- Configure Docker
  - Multi-stage **_Dockerfile_**
  - **_docker-compose.yml_** wiring app + Postgres + Redis + Kafka placeholders
- Configure GitHub Actions
  - CI pipeline: build → unit test → lint
  - ranch protection on **_main_** (per Git strategy)
- Setup Logging
  - Logback structured JSON output
  - Correlation/trace ID filter per request
- Swagger
  - **_springdoc-openapi_** integration, base API info
- Exception Handling
  - **_GlobalExceptionHandler_** (**_@ControllerAdvice_**)
  - Standard **_ApiResponse_** envelope + **_ErrorCode_** enum

**Definition of Done**
- **_docker-compose up_** boots app + DB successfully
- **_/swagger-ui_** and **_/actuator/health_** reachable
- CI pipeline green on push to any branch
- A thrown domain exception returns a consistent JSON error shape

## Sprint 2 — Authentication
**Goal:** Users can securely register, log in, and access role-protected endpoints.

### Tasks
- **Register** — user entity + migration, uniqueness validation, password hashing (BCrypt/Argon2)
- **Login** — credential check, issue access + refresh token pair
- **JWT** — **_JwtTokenProvider_** (generate/validate), JWT filter in the Security filter chain
- **Refresh Token** — Redis or DB-backed storage, rotation on use, **_/auth/refresh_** endpoint
- **Role** — RBAC (**_USER_**, **_ADMIN_**, **_MERCHANT_**), **_@PreAuthorize_** on protected endpoints
- **Security** — stateless session config, CORS policy, rate limiting on **_/auth/*_** (Bucket4j) to blunt brute-force attempts

**Definition of Done**
- Register → Login → access a protected endpoint works end-to-end via Postman/curl
- Expired/invalid JWT returns 401; wrong role returns 403
- Refresh token rotates and old token is invalidated after use
- Unit tests cover token generation/validation; integration test covers the full auth flow

## Sprint 3 — Wallet
**Goal:** Core wallet and ledger operations — the financial core of the platform.

### Tasks
- Wallet — **_Wallet_** domain model, JPA entity + migration, wallet creation use case
- Deposit — **_DepositUseCase_** writing a debit/credit entry pair to the ledger
- Withdraw — **_WithdrawUseCase_** with insufficient-balance check
- Balance — computed as **_SUM()_** over ledger entries (never a mutable balance column); **_GET /wallets/{id}/balance_**
- Transaction History — paginated **_GET /wallets/{id}/transactions_**, filterable by date range/type

**Definition of Done**
- Deposit and withdrawal amounts are always traceable to specific ledger rows
- Balance endpoint result always equals the sum of that wallet's ledger entries (write a test asserting this invariant)
- Concurrent deposit + withdrawal on the same wallet doesn't corrupt the balance (basic concurrency test)
- Transaction history paginates correctly and is covered by an integration test

## Sprint 4 — Transfer
**Goal: **Reliable, idempotent, asynchronous wallet-to-wallet transfers.

### Tasks
- **Money Transfer** — **_TransferFundsUseCase_** orchestrating both wallets atomically; acquire locks in a consistent order to avoid deadlock
- **Kafka** — **_transaction-events_** topic, producer config
- **Notifications** — outbox table + **_OutboxPublisherJob_**; notification module consumes events, stub email/webhook send
- **Retry** — consumer retry with backoff; failed messages routed to a dead-letter topic
- **Idempotency** — **_Idempotency-Key_** header handling (custom annotation + AOP or filter), Redis-backed store with TTL

**Definition of Done**
- Transfer between two wallets is atomic under concurrent load (load test with simultaneous transfer requests, verify no lost/duplicated funds)
- Retrying a request with the same idempotency key returns the original result, doesn't re-execute
- A poison message lands in the dead-letter topic instead of blocking the consumer
- Notification event is visible end-to-end in logs or a Kafka UI (e.g. Kafdrop)

## Sprint 5 — Performance
**Goal:** Make the system measurably fast and observable under load.

### Tasks
- **Redis** — read-through cache for balance lookups, invalidated on write
- **Pagination** — standardize **_page/size/sort_** params across all list endpoints
- **Query Optimization** — index **_ledger_entries(wallet_id, created_at)_**; audit and fix N+1 queries (enable Hibernate statistics)
- **Monitoring** — Micrometer + Prometheus scrape endpoint
- **Metrics** — Grafana dashboard: request latency, error rate, transactions/sec, cache hit ratio

**Definition of Done**
- k6 load test report committed to **_/docs_**, with p95/p99 latency numbers
- Grafana dashboard runs locally via docker-compose and shows live metrics
- No N+1 queries remain on the primary wallet/transfer endpoints (verified via Hibernate stats)
- Cache hit ratio is visible and >0% under repeated balance reads

## Sprint 6 — Deployment
**Goal:** Ship a live, reviewable deployment with a working CI/CD pipeline.

### Tasks
- Docker — finalize production multi-stage Dockerfile, minimize final image size
- Kubernetes — Deployment/Service/ConfigMap/Secret manifests (or Helm chart), validated locally via Minikube/kind
- AWS — provision RDS (Postgres), ElastiCache (Redis), MSK or self-managed Kafka; deploy to ECS or EKS
- CI/CD — extend GitHub Actions: build → test → containerize → push to registry → deploy
- Load Test — k6/Gatling scenario simulating realistic concurrent transfer traffic; publish results

**Definition of Done**
- App is reachable via a public URL
- Merge to **main** triggers an automatic deploy through the pipeline
- Load test results and architecture diagram are in the repo's **/docs**
- README updated with setup instructions, architecture overview, and demo walkthrough


## Summary
| Sprint | 	Focus		      | Key Risk to Watch
| ------ | -------------- | ---------------------------------------------------------------------
| 1	     | Infrastructure	| Skipping CI setup now costs more later — don't defer it
| 2	     | Authentication	| Refresh token rotation logic is easy to get subtly wrong
| 3	     | Wallet	        | Never let balance become a mutable column "just for now"
| 4	     | Transfer       | Lock ordering — inconsistent order across two wallets causes deadlocks
| 5	     | Performance    | Don't cache without a clear invalidation story
| 6	     | Deployment	    | Leave real time for the load test — it usually surfaces one more bug
