# Digital Wallet Platform — Sprint Planning

Sprints deliver **vertical slices across the Final service map**, not a single modular monolith. HTTP paths follow [FInal/03. ApiSpecification.yaml](11.%20ArchitectureDesign/FInal/03.%20ApiSpecification.yaml). Money model follows Final ERD: wallet snapshot + `version`; ledger double-entry via **internal REST**.

Backlog story IDs (`AUTH-01`, `WALLET-01`, …) live in `05. ProductBacklog.md`. Map them onto the slices below; if a backlog “Sprint N” column disagrees with this file, **this delivery plan wins for sequencing**, Final wins for architecture.

## Sprint 0 — Platform skeleton
**Goal:** Every intended deployable exists as a bootable module with CI, even if APIs are health-only.

### Tasks
- Monorepo layout from Final §10 (`api-gateway`, eight business services, `config-server`, `discovery-server`, `infrastructure/`)
- Java 21 + Spring Boot 3.x per service; Maven parent
- Docker Compose: Postgres databases named as in the ERD, Redis, Kafka
- GitHub Actions: build → unit test → lint per module
- Shared conventions: `ApiResponse` / `ErrorCode`, correlation ID filter, structured JSON logs
- Gateway routes for `/api/v1/auth/**` stub; `/internal/v1/**` not published
- Optional: scaffold `web-app/` (Vite + React + TypeScript); CORS origin for the Vite port on the Gateway — **does not block** Java CI

**Definition of Done**
- `docker compose up` starts infra + Gateway + Identity (health)
- CI green on pull requests to `main`
- Branch protection on `main` (see Git strategy)

## Sprint 1 — Identity + Gateway
**Goal:** Register, OTP, login, refresh, logout through the Gateway.

### Backlog
`AUTH-01`–`AUTH-07`, `RBAC-01`–`RBAC-02` (seed `CUSTOMER`, `MERCHANT`, `ADMIN`)

### Tasks
- Identity: users, credentials, OTP, refresh tokens, sessions (`identity_db`)
- JWT access + refresh; Gateway validates JWT (ADR-008)
- Rate limit `/api/v1/auth/**`
- OpenAPI paths: `/api/v1/auth/register|login|refresh|logout|verify-otp|…`

**Definition of Done**
- Register → verify OTP → login → call a protected stub via Gateway
- Invalid JWT → 401; wrong role → 403
- Integration tests (Testcontainers) cover the auth flow

## Sprint 2 — Customer & KYC + Admin review
**Goal:** Customer profile and KYC submit/approve.

### Backlog
`PROFILE-01`–`PROFILE-02`, `KYC-01`–`KYC-06`, `ADMIN-01` (customer list), `RBAC-03`

### Tasks
- Customer & KYC service (`customer_db`); `user_id` logical ref to Identity
- Admin KYC approve/reject (`/api/v1/admin/kyc/applications/{id}/approve|reject`)
- Events: `CustomerCreated`, `KycApproved` / `KycRejected`

**Definition of Done**
- Customer cannot read another customer’s KYC
- Approval is audited (Admin service audit log)

## Sprint 3 — Wallet + Ledger
**Goal:** Operational wallet plus accounting SoR.

### Backlog
`WALLET-01`–`WALLET-06`

### Tasks
- Wallet: create on allowed onboarding event; `available_balance`, `reserved_balance`, `version`
- `POST /api/v1/wallet/deposits` and `POST /api/v1/wallet/withdrawals`
- Ledger service: `POST /internal/v1/ledger/entries`; balanced debit/credit; append-only
- Wallet (or Transfer later) calls Ledger **synchronously** on money movement
- Outbox on wallet writes for `MoneyDeposited` / `MoneyWithdrawn` (consumers: notify/audit — not a substitute for the ledger POST)

**Definition of Done**
- Deposit/withdraw update snapshot and post ledger entries
- Concurrent updates retry on version conflict (no silent lost update)
- Ledger invariant: per transaction, SUM(debit) = SUM(credit)
- Paths match OpenAPI (`/api/v1/wallet/balance`, not `/wallets/{id}/balance`)

## Sprint 4 — Transfer
**Goal:** Idempotent P2P transfer orchestration.

### Backlog
`TRANS-01`–`TRANS-02`, `TRANS-04`–`TRANS-06`, `TRANS-09`–`TRANS-10`, `NOTIF-01`–`NOTIF-02` (stub channel)

### Tasks
- Transfer service: `POST /api/v1/transfers`, beneficiaries, `idempotency_records`
- Sync: Risk evaluate → Wallet debit/credit → Ledger entries
- Outbox → Kafka `TransferCompleted` → notification consumer (stub email)
- Retry / DLQ for poison messages

**Definition of Done**
- Same `Idempotency-Key` does not double-post
- Two-wallet transfer is consistent with wallet snapshots and balanced ledger
- Gateway never exposes Ledger

## Sprint 5 — Payment & observability
**Goal:** Merchant/QR payment slice plus metrics.

### Backlog
`MERCH-01`–`MERCH-04`, `QR-01`–`QR-05`, `TXN` history as exposed by Wallet/Transfer/Payment list APIs

### Tasks
- Payment & Merchant service; QR scan/confirm per OpenAPI
- Redis cache optional for `GET /api/v1/wallet/balance` with invalidation on write
- Micrometer + Prometheus; Grafana in Compose
- Indexes on hot tables (`ledger_entries`, transfer created_at)

**Definition of Done**
- QR confirm posts payment + wallet + ledger (same pattern as transfer)
- Actuator metrics scraped locally

## Sprint 6 — Admin, risk hardening, deploy
**Goal:** Back-office + pipeline to a reviewable environment.

### Backlog
`ADMIN-02`–`ADMIN-05`, `FRAUD-01`–`FRAUD-02` (rule stub), `OPS-*` CI/CD

### Tasks
- Admin freeze/unfreeze, dashboard, audit-logs, maker-checker `approvals`
- Risk alerts persisted; high-risk can block transfer
- Kubernetes manifests or Helm; GitHub Actions: test → image → deploy
- Load test transfers (k6); results under `docs/`

**Definition of Done**
- App reachable via Gateway URL
- Merge to `main` deploys through CI
- README documents as-built services and how to run Compose

## Frontend (optional, after each Java slice)

Screens in `17. FrontendUi.md` may lag the backend by a sprint. Do **not** hold Wallet/Transfer DoD for React. If time remains in a sprint, wire the matching page to Gateway only.

## Summary
| Sprint | Focus | Key risk |
| ------ | ----- | -------- |
| 0 | Multi-module skeleton + CI | Do not collapse into one `wallet-service` monolith |
| 1 | Identity + Gateway JWT | Refresh rotation and Gateway vs service authz |
| 2 | Customer / KYC | Logical `user_id` / `customer_id` — no cross-DB FK |
| 3 | Wallet snapshot + Ledger SoR | Always POST ledger on the request path; keep `version` |
| 4 | Transfer orchestration | Lock/version order; idempotency; outbox not dual-write |
| 5 | Payment / QR + metrics | Same money pattern as transfer |
| 6 | Admin / risk / deploy | Leave time for load test |
