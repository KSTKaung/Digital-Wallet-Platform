# Inter-Service Contracts

Implements Final Architecture §4–§7 and ERD §10 without changing those files.

## Public vs internal

| Surface | Prefix | Exposed on API Gateway |
| ------- | ------ | ---------------------- |
| Customer / merchant / admin HTTP | `/api/v1/**` | Yes (see Gateway routing table in Final) |
| Ledger | `/internal/v1/ledger/**` | **No** |
| Risk evaluate | `/internal/v1/risk/**` | **No** |

Gateway routing (Final):

```
/api/v1/auth/**       → Identity
/api/v1/customers/**  → Customer & KYC
/api/v1/kyc/**        → Customer & KYC
/api/v1/wallet/**     → Wallet
/api/v1/transfers/**  → Transfer
/api/v1/beneficiaries/** → Transfer
/api/v1/payments/**   → Payment & Merchant
/api/v1/merchants/**  → Payment & Merchant
/api/v1/admin/**      → Admin & Operations
/api/v1/notifications/** → Risk & Notification
```

## Money movement (synchronous)

```
Customer
  → Gateway  POST /api/v1/transfers
  → Transfer Service
       1. Idempotency-Key
       2. Validate + limits
       3. GET/POST internal risk evaluate (sync)
       4. Wallet: debit sender / credit receiver (snapshot + version)
       5. Wallet → Ledger POST /internal/v1/ledger/entries (double-entry)
       6. Local commit + outbox row
  → 201 to client
  → Outbox publisher → Kafka TransferCompleted
       → Notification, Audit, Analytics (async)
```

Kafka **must not** be the way ledger rows are written. Ledger posts happen on the request path over internal REST.

## Wallet vs ledger

| Store | Responsibility |
| ----- | -------------- |
| `wallet_db.wallets` | Operational snapshot: `available_balance`, `reserved_balance`, `version` (ADR-009) |
| `ledger_db` | Accounting SoR: balanced debit/credit entries; append-only; reversals are new transactions |

## Logical references (never physical FKs across DBs)

Resolve via API or event payload (ERD §10), for example:

- `customers.user_id` → `identity_db.users.id` (`CustomerCreated`)
- `wallets.customer_id` → `customers.id` (`CustomerCreated` / `KycApproved`)
- `transfers.sender_wallet_id` → `wallets.id` (Wallet API at transfer time)
- `ledger_accounts.owner_reference` → wallet or merchant id (`WalletCreated` / `MerchantApproved`)

## Event envelope

Use Final §7: `eventId`, `eventType`, `eventVersion`, `occurredAt`, `producer`, `correlationId`, `causationId`, `payload`. Full catalog remains in `11. ArchitectureDesign/04. EventDesign.md`.

## Idempotency

`Idempotency-Key` on all money-movement POSTs (`/wallet/deposits`, `/wallet/withdrawals`, `/transfers`, `/payments`, refunds). Store in Redis and/or `idempotency_records` (Transfer ERD).
