# Frontend UI (React) — demonstration layer

This project is **backend-first** (Java 21 / Spring Boot microservices). React is a **thin client** that calls the API Gateway. It does not own domain rules, ledgers, or a ninth bounded context.

**Do not change** `11. ArchitectureDesign/FInal/*` for this. Public HTTP stays [03. ApiSpecification.yaml](11.%20ArchitectureDesign/FInal/03.%20ApiSpecification.yaml).

## Scope

| In scope | Out of scope (unless product later expands) |
| -------- | -------------------------------------------- |
| SPA(s) for **demo and operator screens** | Native iOS/Android (vision “mobile-first” can wait) |
| Customer flows that already have OpenAPI | Duplicating KYC/AML/ledger logic in the browser |
| Admin screens for freeze, KYC review, audit | Calling `/internal/v1/**` from the browser |
| JWT access token after `POST /api/v1/auth/login` | Server-side rendering as the architecture |

Recommended: **one Vite + React + TypeScript app** with route groups `/` (customer) and `/admin` (admin). Split into two apps only if the admin UI grows large.

## Rules

1. Browser talks **only** to `http://localhost:8080` (Gateway). Never to Wallet, Ledger, or other service ports.
2. Money amounts, limits, KYC outcomes, and RBAC come **from the API**. The UI displays and confirms; it does not decide.
3. Store access token in memory (or a short-lived cookie strategy later). Do not put refresh tokens in `localStorage` for a banking demo if you can avoid it.
4. Send `Authorization: Bearer` and `Idempotency-Key` on money-movement POSTs.
5. CORS is configured **on the Gateway**, origin = Vite dev server (e.g. `http://localhost:5173`).

## Suggested screens (follow backend sprints)

| After backend slice | UI |
| ------------------- | -- |
| Sprint 1 Identity | Register, OTP, login, logout |
| Sprint 2 KYC | Profile, submit KYC, status; admin approve/reject |
| Sprint 3 Wallet | Balance, deposit, withdraw, history |
| Sprint 4 Transfer | Transfer form, beneficiaries, status |
| Sprint 5 Payment | Merchant QR confirm (camera optional / paste QR ref) |
| Sprint 6 Admin | Dashboard, freeze, fraud list, audit |

Backend Definition of Done **does not** require these screens. UI is a follow-on demo per slice.

## Stack (frontend only)

- React 18+
- TypeScript
- Vite
- React Router
- Fetch or a thin API client generated from OpenAPI (optional)
- ESLint + Prettier; no Java in this module
