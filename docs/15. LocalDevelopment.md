# Local Development

Matches Final Architecture: clients talk to **API Gateway** (`http://localhost:8080`). Ledger and Risk are **not** routed on the public gateway.

## Prerequisites

- JDK 21
- Maven 3.9+
- Docker Desktop (Compose)

## Target Compose topology

```
localhost:8080  →  api-gateway
                   ├── identity-service
                   ├── customer-kyc-service
                   ├── wallet-service
                   ├── transfer-service
                   ├── payment-merchant-service
                   ├── risk-notification-service
                   └── admin-operations-service

internal only     ledger-service
                  risk evaluate API (same risk-notification-service or dedicated)

infra             postgres × N (or one Postgres instance, one database per service name)
                  redis
                  kafka
                  config-server
                  discovery-server (Eureka, or skip if using Compose DNS names)
```

Database names from Final ERD: `identity_db`, `customer_db`, `wallet_db`, `transfer_db`, `payment_db`, `ledger_db`, `risk_db`, `notification_db`, `admin_db`.

No service may query another service’s tables.

## Suggested first boot order

1. Infra: Postgres, Redis, Kafka, Config, Discovery.
2. Identity + Gateway (register / login).
3. Customer & KYC.
4. Wallet + Ledger (deposit/withdraw + internal ledger posts).
5. Transfer (orchestration + outbox).
6. Remaining services.

Until all modules exist, a thin Gateway can proxy only the services that are running.

## Configuration

- Per-service `application.yml` plus Config Server overlays for shared Kafka/Redis/JWT settings.
- Secrets in `.env` / `application-local.yml` — never commit real credentials (`12. TechnologyDocument/03. GitStrategy.md`).
- Public JWT validation at the Gateway (Final ADR-008). Each service still enforces `@PreAuthorize`.
